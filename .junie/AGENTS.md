### Project Guidelines

#### Changelog Conventions
- **Dates**: Always include dates in `YYYY-MM-DD` format alongside release/version names (e.g., `### Beta 1 - 2026-11-01`).
- **Baseline Events**: Include the initial release (Beta 1) as the foundational event in the changelog.
- **Categorization**: Keep change type identifiers (`Fixed`, `Added`, `Changed`, `Removed`) inline on the same line as the bullet entry (e.g., `- **Fixed**: ...`) rather than grouping under subheadings to keep entries compact.
- **Specificity**: Explicitly reference affected model filenames (e.g., `timing-belt-holder-bottom.3mf`) and provide actionable descriptions.

#### Documentation & Formatting
- Adhere to the repository's Markdown conventions: use level 3 headers (`###`) and smaller (`####`) instead of level 1 (`#`) or level 2 (`##`) headers.
